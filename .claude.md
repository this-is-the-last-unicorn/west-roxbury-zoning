# Cursor AI Instructions

## Project Overview

This is the **West Roxbury Zoning Analysis** tool — a full-stack application for analyzing zoning regulations, parcel data, and land use in West Roxbury, Boston. It combines GIS mapping with structured zoning data to help residents, developers, and city planners understand what can be built where.

### Tech Stack

- **Runtime**: Bun
- **Frontend**: Next.js 16 + Tailwind CSS 4 + shadcn/ui
- **API**: Express + Prisma + PostgreSQL
- **Mapping**: Mapbox GL JS
- **Validation**: Zod (mandatory for all external data)
- **Type Safety**: TypeScript strict mode (NO `any` types allowed)
- **Logging**: Pino + Sentry (version-tracked releases)

### Key Conventions

- **Workspace packages** use `@app/` prefix (e.g., `@app/web`, `@app/database`)
- **Doppler** manages environment variables; `dev:local` scripts bypass it for offline work
- **Render** is the hosting platform via `render.yaml` Blueprint
- **All localhost URLs** in code are dev fallbacks — production URLs come from env vars
- **Data pipeline**: `tools/pipeline/load_data.py` is the source of truth for all zoning math and parcel data ingestion

### File Organization

```
apps/
├── web/              # Next.js frontend (maps, zoning explorer)
├── api/              # Express API (zoning queries, parcel data)
packages/
├── database/         # Prisma schema & client (zoning/parcel models)
├── logger/           # Pino + Sentry + version tracking
tools/
├── pipeline/         # Python data pipeline (load_data.py)
├── cli/              # CLI for seeding & dev tasks
instructions/         # Development guidelines
```

## CRITICAL REQUIREMENTS

### ABSOLUTE PROHIBITIONS

1. **NEVER use `any` type** — Use proper TypeScript types, `unknown`, or Zod inference
2. **NEVER skip validation** — All external data must be validated with Zod schemas
3. **NEVER ignore TypeScript errors** — All type errors must be resolved
4. **NEVER use `@ts-ignore` or `@ts-expect-error`** without exceptional justification

### Type Safety Requirements

```typescript
// ❌ FORBIDDEN
const data: any = req.body

// ✅ REQUIRED
const bodySchema = z.object({
  parcelId: z.string(),
  zoningCode: z.string(),
})
const data = bodySchema.parse(req.body)

// ✅ For unknown external data
const result: unknown = await someExternalAPI()
const validatedResult = resultSchema.parse(result)
```

## Development Workflow

### Before Starting Any Task

1. **Read the relevant instruction files** in `/instructions/`
2. **Examine existing code** for patterns before creating new implementations

### Quality Assurance (RUN BEFORE EVERY COMMIT)

```bash
bun run check          # Runs lint + typecheck + format in one command
bun test               # All tests must pass
```

### Individual Commands

```bash
bun run typecheck      # Zero TypeScript errors required
bun run lint           # Zero ESLint warnings required
```

### Database Operations

```bash
bun run db:generate    # Generate Prisma client after schema changes
bun run db:migrate     # Run database migrations
bun run db:studio      # Open Prisma Studio for data inspection
bun run db:reset       # Reset database (DESTRUCTIVE)
```

### Build & Deployment

```bash
bun run build          # Build all applications
bun run build:web      # Build web app only
bun run build:api      # Build API only
bun run start          # Start production servers
```

## Pre-Completion Checklist

Before marking any task complete, verify:

- [ ] All TypeScript errors resolved (`bun run typecheck`)
- [ ] All ESLint warnings resolved (`bun run lint`)
- [ ] All tests pass (`bun test`)
- [ ] No `any` types used anywhere
- [ ] Error handling implemented properly
- [ ] Code follows existing patterns in the repository
